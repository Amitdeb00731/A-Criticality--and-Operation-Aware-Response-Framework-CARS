# Reproducing CARS

Three levels, in increasing hardware need: the decision logic (any machine), the full defended attack in emulation (a Linux host with root), and the hardware testbed (real PLCs). **Levels 1–2 need no ICS hardware** — one Linux machine is enough. Full requirements and hardware tiers are in [`HARDWARE.md`](HARDWARE.md).

## 1. Decision logic and config parity (any machine)

```bash
cd framework
pip install -e '.[dev]'
PYTHONPATH=. pytest tests/ -q
```

- `tests/test_config_parity.py` proves the shipped `examples/site.testbed.yaml` reproduces the engine's built-in policy exactly.
- `tests/test_emulation_core.py` starts the software S7 PLC and runs the tank co-simulation headless — a genuine self-test with no hardware.

## 2. Full defended attack in emulation (Linux + root)

Needs Mininet, Open vSwitch and Snort. The physical Siemens CPU is replaced by a software S7 server; everything else (controller, Snort, OVS, the S7/Modbus wire traffic) is real.

```bash
cd framework
pip install -e '.[controller,emulation]'
CARS_SITE=examples/site.testbed.yaml osken-manager ../06_Build/cars_engine.py   # controller
sudo emulation/demo.sh                                                          # fabric + PLCs
mininet> atk python3 ../06_Build/s7_write.py 192.168.2.10                        # attack
mininet> ovsgw ovs-ofctl -O OpenFlow13 dump-flows ovsgw | grep 0xca             # the isolate
```

Detail: `framework/emulation/README.md`.

## 3. Hardware testbed (real PLCs)

The system as built runs from `06_Build/` as the `cars-*` systemd services (controller, Snort bridge, flow-audit, remediation, dashboard). Dependencies: `06_Build/requirements.txt`; Snort and Open vSwitch are system packages. Topology and cold-start: `06_Build/AS_BUILT_TOPOLOGY.md`, `06_Build/COLD_START.md`.

### Which harness reproduces which claim

| Claim | Harness |
|---|---|
| 100% decision accuracy over 2,078 cases | `07_Evaluation/overnight/vast_accuracy.py` (data: `results/vast/vast.csv`) |
| Reaction window (median 7.6 ms) | `07_Evaluation/cars2_mttm.py` (and `06_Build/cars_mttm.sh`) |
| Criticality-scaled response ladder | `06_Build/cars_criticality_proof.sh` |
| Wire-level block-and-maintain (0 vs 973) | `06_Build/cars_wire_campaign.sh` / `_disarmed.sh` |
| Event-driven flow-integrity (30/30) | `07_Evaluation/overnight/gap4_flowmonitor/cars_flowmonitor.py` (data: `results/gap4_flowmonitor/transient_eventdriven.csv`) |
| Process transparency (armed ≈ disarmed) | data: `07_Evaluation/overnight/results/e2/interleaved.csv` |
| Controller-reconnection jitter | data: `07_Evaluation/overnight/results/jitter/timeline.csv` |

The repository keeps the harness scripts and the specific result files the report cites; the bulk raw output (full pcaps and dumps) is not shipped — it is regenerated by re-running the harnesses above.
