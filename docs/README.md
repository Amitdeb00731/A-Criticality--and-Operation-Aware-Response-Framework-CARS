# Design and validation records

The engineering record behind the dissertation and the framework, kept for reproducibility and rigour. The polished account is in [`../report/`](../report/); the reproducible system is in [`../framework/`](../framework/) and [`../06_Build/`](../06_Build/).

- **design/** — the design notes (A2–A5), the criticality framework, the decision log (CC-1..CC-101), and the gap-and-novelty analysis: why CARS is built the way it is.
- **validation/** — validation and verification reports, test matrices, and the consistency audit from the evaluation days: the evidence behind the Chapter 4 claims.
- **planning/** — the governing plans: the report writing plan (`REPORT_PLAN.md`) and the framework roadmap (`CARS_FRAMEWORK_PLAN.md`).
- **offensive/** — the attacker-VM setup and the pen-test playbook, for reproducing the evaluation. These describe testing on an isolated testbed; read [`../ETHICS.md`](../ETHICS.md) first, and use for research and authorised testing only.
